# Отчет по лабораторной работе 2

## Что было сделано

Во второй лабораторной работе проект Wine Quality MLOps был доработан для повторного использования модели из Git-репозитория и для работы сервиса модели с PostgreSQL.

Итоговое состояние опубликовано в ветке `develop` репозитория `AkhatKhusainov/DevOpsStudy`.

## Реализация требований

### 1. Репозиторий и работа через Git

- Для дальнейшего переиспользования проекта создана и опубликована ветка разработки `develop`.
- Актуальное состояние Lab2 зафиксировано коммитом `08a16a9`.
- Репозиторий можно использовать как источник модели и сервиса в следующих лабораторных работах.

### 2. Взаимодействие сервиса модели и базы данных

- FastAPI-сервис сохраняет результаты инференса в PostgreSQL.
- Реализованы эндпоинты для просмотра состояния БД, сводки по загруженным данным и последнего предсказания.
- Для слоя доступа к данным добавлен `SqlAlchemyPredictionStore`.

### 3. Аутентификация и авторизация при доступе к БД

- Параметры подключения к БД не захардкожены в исходном коде.
- Адрес, порт, имя базы, пользователь и пароль передаются через переменные окружения, `.env`, GitHub Secrets/Variables или Jenkins credentials.
- Для Jenkins используется credential `postgres-password`.

### 4. Наполнение базы данных наборами данных

- Реализован seed-скрипт `scripts/seed_database.py`.
- В PostgreSQL загружаются подготовленные наборы `train` и `test`.
- По результатам локальной проверки в БД было загружено:
  - `train`: 1087 записей
  - `test`: 272 записи

### 5. Переиспользование CI pipeline

- Для второй лабораторной работы используется `jenkins/lab2-ci.Jenkinsfile`.
- Pipeline выполняет:
  - установку зависимостей;
  - `dvc repro`;
  - `pytest`;
  - сборку Docker image;
  - push image в Docker Hub;
  - генерацию `dev_sec_ops.yml`.

### 6. Переиспользование CD pipeline

- Для второй лабораторной работы используется `jenkins/lab2-cd.Jenkinsfile`.
- Pipeline выполняет:
  - запуск `postgres + api` через `docker compose`;
  - загрузку train/test наборов в БД;
  - ожидание готовности API;
  - функциональное тестирование по сценарию.
- `lab2-ci` может опционально вызвать `lab2-cd` после успешного завершения.

### 7. Приложение результатов функционального тестирования и скриптов CI/CD

- В папку результатов включен файл `functional-test-report.json` с актуальным отчетом функционального тестирования.
- Список используемых CI/CD-скриптов приведен в файле `Приложенные_скрипты_CI_CD.txt`.

## Результаты проверки

Локальный функциональный сценарий был успешно выполнен на стеке `postgres + api`.

Проверенные шаги:

- `GET /health` -> `200 OK`
- `GET /training-data/summary` -> `200 OK`
- `POST /predict` -> `200 OK`, результат сохранен в PostgreSQL
- `GET /predictions/latest` -> `200 OK`

По результатам сценария:

- `database_status.enabled = true`
- `database_status.connected = true`
- `stored_in_db = true`
